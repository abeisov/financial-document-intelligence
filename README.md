# Financial Document Intelligence

Локальный web-MVP и CLI для анализа финансовых документов. В web-режиме RAGFlow
хранит документы, разбивает их на фрагменты и выполняет первичный поиск; внешний
Reranker уточняет релевантность, а Qwen отвечает строго по найденным источникам.

## Web-MVP

В браузере можно:

- создать или выбрать Dataset RAGFlow;
- загрузить PDF, DOCX, XLSX, CSV, TXT, презентацию или изображение (лимит задаётся `MAX_UPLOAD_MB`, по умолчанию 4 МБ);
- увидеть прогресс индексации;
- задать вопрос по загруженному документу;
- получить ответ с отдельными фактами, интерпретацией и цитатами.

Версия однопользовательская: вместо регистрации — Basic-доступ по паролю из переменной окружения.

## Быстрый старт

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Заполните локальный `.env` по примеру `.env.example`. Не добавляйте реальные документы
и `.env` в Git.

## Запуск

```bash
uvicorn src.web:app --reload            # сайт: http://127.0.0.1:8000
```

Для терминальной контрольной цепочки:

```bash
python scripts/make_test_pdf.py          # генерирует фикстуру и ground_truth.json
python -m src.cli                        # полный прогон, PASS/FAIL по этапам
python -m src.cli --pdf path/to/file.pdf # свой документ
python -m src.cli --json                 # отчёт в JSON
```

Код возврата: `0` — PASS, `1` — FAIL, `2` — файл не найден.

## Размещение на Vercel

Приложение разворачивается как одна Python-функция, фронтенд остаётся обычной
статикой, отдельный фронтенд-фреймворк не нужен.

| Файл | Назначение |
| --- | --- |
| `api/index.py` | точка входа: Vercel ищет ASGI-объект `app`, логика остаётся в `src/web.py` |
| `vercel.json` | все маршруты переписываются на функцию, `maxDuration` 60 с, тесты и данные исключены из бандла |
| `.vercelignore` | что не уезжает на платформу: окружение, артефакты, документы, `.env` |

Переменные окружения задаются в разделе Environment Variables проекта Vercel —
в репозиторий они не попадают:

```
QWEN_API_KEY, QWEN_URL, QWEN_MODEL
EMBEDDER_API_KEY, EMBEDDER_URL, EMBEDDER_MODEL
RERANKER_API_KEY, RERANKER_URL, RERANKER_MODEL
RAGFLOW_URL, RAGFLOW_API_KEY
RAGFLOW_DATASET_NAME, RAGFLOW_CHUNK_METHOD
APP_USER, APP_PASSWORD      # доступ к сайту
MAX_UPLOAD_MB               # лимит загрузки
```

### Ограничения платформы

- тело запроса к функции на Vercel ограничено **4,5 МБ**, поэтому лимит загрузки
  по умолчанию выставлен в 4 МБ и показывается в интерфейсе из `/api/health`;
  локально его можно поднять переменной `MAX_UPLOAD_MB`;
- файловая система функции доступна только на чтение (кроме `/tmp`): CLI-прогон
  с записью в `artifacts/` рассчитан на локальный запуск;
- `maxDuration` 60 секунд: индексация в RAGFlow идёт асинхронно, браузер опрашивает
  статус документа, поэтому в лимит укладывается.

### Защита доступа

Если задан `APP_PASSWORD`, каждый запрос, кроме `/api/health`, требует Basic-входа.
Пароль хранится только в переменных окружения, в браузер и в HTML не попадает.
Без переменной защита выключена — это режим локальной разработки.

## Настройка RAGFlow

В `.env` должны быть `RAGFLOW_URL` и `RAGFLOW_API_KEY`. Необязательные настройки:

```dotenv
RAGFLOW_DATASET_NAME=financial-documents
RAGFLOW_CHUNK_METHOD=naive
```

В самом кабинете RAGFlow должен быть настроен embedding-провайдер и выбрана модель
эмбеддингов по умолчанию. После этого Dataset можно создать прямо на сайте. Qwen и
Reranker вызываются через уже настроенные переменные `.env`; их ключи браузеру не
передаются.

Если RAGFlow отвечает, что API-ключ не имеет права создавать Dataset, создайте его
один раз в кабинете RAGFlow и нажмите кнопку обновления на сайте. Загрузка и поиск
после этого продолжат работать через API.

## Цепочка ответа

1. RAGFlow принимает документ, разбирает и индексирует его.
2. RAGFlow Retrieval API возвращает подходящие фрагменты.
3. Внешний Reranker переставляет фрагменты по релевантности.
4. Qwen получает только пять лучших фрагментов.
5. Сервер проверяет ID цитат, цитаты и все числа в ответе.

Embedder используется самим RAGFlow при индексации. Отдельный Embedder из `.env`
остаётся частью CLI-проверки и резервной цепочки.

## Тесты

```bash
pytest              # оффлайн-тесты CLI, web API и проверки обоснованности
RUN_LIVE=1 pytest   # плюс интеграционные тесты с обращением к API
```

## Этапы прогона

| Этап | Что проверяется |
| --- | --- |
| `preflight` | доступность Qwen, embedder, reranker, RAGFlow |
| `extraction` | 3–10 страниц, текстовый слой, контрольные значения на своих страницах |
| `chunking` | уникальные `chunk_id`, сохранение номера страницы, покрытие страниц |
| `embedding_search` | числовой вектор, попадание нужной страницы в top-k |
| `reranking` | нужный фрагмент поднят на первое место |
| `qwen_answers` | ответы на четыре контрольных вопроса содержат известные значения |
| `citations` | у каждого ответа есть страница и `chunk_id` |
| `no_outside_knowledge` | числа ответа есть в контексте; отсутствующий факт даёт `insufficient_evidence` |
| `artifact_safety` | в артефактах нет секретов и дословной выгрузки документа |

## Артефакты

- `artifacts/analysis.json` — ответы, ссылки на источник, метрики поиска и reranking.
- `artifacts/test_report.json` — PASS/FAIL по каждому этапу и итог.

Оба файла исключены из Git и не содержат ключей, паролей и полного текста документа.

## Тестовый документ

`scripts/make_test_pdf.py` собирает вымышленный отчёт ТОО «Каспий Агро Трейд» на 5 страниц
с известными значениями за 2023 и 2024 годы (P&L, баланс и долг, ДДС, коэффициенты).
Эталон для проверок хранится в `data/ground_truth.json`.
